# 年代大事

给改 `content/eras.yaml`、`content/events/eras.yaml` 和关口线的人看。规则代码在 `server/src/era.ts`，内容校验在 `tools/build-content.mjs`（「年代大事」那一段）。

## 两个人同岁

两个人同一年生。一局只有一个出生年代（`LifeState.cohort`），两个人共用；日历年、发生过的大事（`LifeState.eras`）也只有一份。
大事落下来时，给在世的两个人都打上同样的 `era_*` 标记；只有 `hits`（落到个人头上的）按各自的标记、岁数分开吃。

同一个活法，生在六十年代和生在〇〇后，三十岁时走得通的路和攒下的钱不一样。这是这一层要做的全部事情。

## 出生年代怎么抽

`content/eras.yaml` 的 `cohorts` 有五个：c65 六十年代中生、c75 七十年代中生、c85 八十年代中生、c92 九十年代初生（`default: true`）、c02 〇〇后。
`weight` 是抽中的权重，现在是 2 / 2 / 2 / 3 / 2。

- `eraPickCohort(c, seed)`：用种子单独起一串随机数（`seed ^ 0x5bd1e995`，先空转一次），按权重抽。**不动 `s.rng`**：同一个种子投胎抽到的家境、天赋、后面每一次随机都和没有年代层时一样，老测试的种子结果不变。
- 新开一局：`main.ts` 调 `lifeCreate(seed, CONTENT, undefined, eraPickCohort(CONTENT, seed))`。
- `lifeCreate(seed, c, legacy, cohortId)` 的第四个参数不写，就是默认年代（c92）。测试、`tools/paths.mjs`、`tools/balance.mjs` 都不写，所以它们跑的是 c92。第四个参数只是给 `s.cohort` 赋值，抽家境天赋都在它之前。
- 再来一世：`eraRebirthCohort(c, seed, 上一世)`，照样按种子抽，抽到和上一世同一个年代就顺着列表往后挪一个。同样两个人，换一个年代再活一回。
- 老存档（v8 及以前）没有 `cohort`，升 v9 时按默认年代算（`save.ts`、`eraRepair`）。存档里的年代 id 在内容里没了，也换回默认。

## 日历年

`eraYear(s, c) = 出生年（cohort.born）+ 今天的岁数`。岁数来自 `lifeTimeAt(s.turn)`：童年一年四天、少年一年两天、青年一年一天、中年三年一天（30、33、36……）、老年五年一天（60、65、70、75、80）。

年份只在引擎里算，**从不给人看**。给人看的是 `decades`：取 `from ≤ 年份` 的最后一条，`name` 是年代名（「九十年代」「千禧年头上」），`look` 是客户端用哪一套街景（现有美术的五个阶段键之一）。
同一个年代名可以写两条，只换 `look`（三〇年代中往后换老年那套街景）。

五个年代的关口落在哪一年：

## 大事什么时候发生

一件大事（`events` 里的一条）在日历年到了 `year` 那一天发生，一局里只发生一次（记进 `s.eras`）。

- **生之前的悄悄生效**：两个人都确认投胎那一刻（`lifeConfirm` → `eraStart`），开局那天是三岁，`year ≤ 出生年 + 3` 的大事一次性补上，只打标记、摘标记，不弹卡、不吃 `hits`、不记长卷。考大学、分配、等分房三件写在 1963 年，对五个年代都是生之前，只当作底下的规矩。
- **过日子时**：新的一天开张之前（`sim.ts` 里 `s.turn` 加一以后、关口和行动之前）跑 `eraTick`。到了年份的大事发生：摘 `clears`、打 `flags`、每个人按顺序吃第一条满足的 `hits`，各记一条 `kind: "era"` 的长卷（`{ era: { id, title, text, decade, hits: { qing?, mei? } } }`）。所以**关口当天已经到年份的大事算数**。
- **跳着过的日子**：中年三年一天、老年五年一天，中间几年的大事在同一天按年份先后补上；`hits` 看的是**当天**的岁数，不是那一年的岁数。
- **`eraSync`**：`worldStartDay` 每天开头再对一遍，今天的年份该有的标记都在，没发生的悄悄补上（不弹卡、不吃 `hits`）。正常过日子 `eraTick` 已经做完了，它管的是跳着过的、修过的存档。
- **`until`**：到这一年，本件发的标记自动摘掉，这件事的线和工钱也就不算了。**当天到 `until` 的不算**（先过期，再看关口）。`until` 不写 = 一直在。
- **`clears`**：发生那一刻摘掉别的大事发的标记（扩招摘掉「考大学」，房改摘掉「等分房」）。
- 一个 `era_` 标记只由一件事发（build-content 查），`until` 才摘得干净。

## 怎么写一件大事

```yaml
  - id: era_xiahai
    year: 1992
    until: 2001            # 可选
    title: 下海            # ≤ 7 字
    text: ……               # ≤ 45 字，两个人看同一段
    flags: [era_xiahai]    # 至少一个，必须 era_ 开头
    clears: [era_xxx]      # 可选，只能摘 era_ 标记，而且得有哪件事发它
    lines:                 # 可选
      m_job.trade: -5
    wages:                 # 可选
      job_trade: 1.25
    hits:                  # 可选
      - requires: { flags: [job_succeed], notFlags: [laid_off], minAge: 22, maxAge: 50 }
        text: 厂里活少了，工钱只开八成。   # ≤ 30 字，只给这个人看
        flags: []          # 可选，加给这个人
        clears: []         # 可选
        money: 40          # 可选，积蓄加减（块），扣不到负数
        savings: 0.85      # 可选，积蓄乘这个数（0~2），先乘后加
```

- **`lines`**：带着本件 `flags` 的人，这条关口线挪多少。键是 `<关口 id>.<选项 id>`，那个选项必须本来就有 `min`。单位是给人看的那一套：**分数线按百分制分**（`-5` = 线低 5 分，build-content 换算成 `min` 的 `-0.5`），**积蓄线、亲近线按块 / 分原样**。挪完不能 ≤ 0，一次不能挪原线的六成以上。build-content 把它编进选项的 `eraLines: [{ flags, d }]`，引擎只读这个。
- **`wages`**：带着本件标记、又带着键里这个标记的人，日程工钱乘这个数（0~3）。几件叠在一起是连乘（`eraWageFactor`，`world.ts` 的 `worldWage` 调它，只乘挣钱的日程）。
- **`hits`**：落到个人头上的。每个人从上往下取第一条 `requires` 满足的，可以一条都不中。生之前的不吃。
- 每件大事至少要动一样：`lines`、`wages`、`hits`，或者有别的内容（行动、关口选项、事件、路线的 `requires`）读它的标记。纯新闻 build-content 不收。
- 内容里读年代一律用 `requires.flags` / `notFlags` 读 `era_*`。关口选项可以要年代标记（`m_settle.unit` 要 `era_fenfang`，`m_settle.quota` 要 `era_huiluo`），但每道关仍要有一个无门槛的兜底。只在某个年代出现的普通事件放在 `content/events/eras.yaml`（现在七件：停薪留职、分房榜、厂门口、排队、课间、占座、头一趟）。

## 判线只走两个入口

- `lifeOptionMin(o, p)`：这个人眼前这条线 = 内容里写的 `min` + 他身上年代标记挪的那一截（`eraLines` 里 `flags` 全带着的才算）。没有线的选项原样返回。
- `lifeOptionCost(ev, o, p)`：看积蓄的线挪了，要掏的钱跟着挪同样的块数。买房线 200、掏 200，房价那件 +40，线是 240、掏的也是 240。

引擎里所有判线的地方都已经换成这两个：`sim.ts` 的 `lifeOptionLock`（上锁）、`lifeReveal`（揭晓）、`lifeTapeGrades` / `lifeGoal`（目标条）、`lifeResolveEvent`（扣钱），`atlas.ts` 的 `atlasOptionShort`（差一点），`world.ts` 的 `worldShadowNeed`（影子盯哪条线）。
**新写判线的代码不要直接读 `o.min` / `o.cost`。**

## 校准口径

现有数值（`milestones.yaml` 的 `min`、`tracks.yaml` 的工钱）是按九十年代初生那一世校的。所以：

- **c92 在五道关的每一条线上挪动都是 0**。唯一靠抵消得来的在 `m_settle`：头一波房价（+15 / +12 / +8）和回落（−15 / −12 / −8）一一对上。c92 三十岁以前走出来的每一条人生，和没有年代层时逐条一样（`node tools/eras.mjs --check` 查）。
- c92 只吃「扫码」一件工钱（摆摊 ×1.1、铺子 ×0.92），两条路都要三十岁以后才走得上，所以三十岁的积蓄不动，四十五岁以后差十来块。
- 别的年代拉开：六十年代生高考难、包分配、分房便宜、三十多岁碰下岗；八十年代生赶上扩招、三十岁房价最高；〇〇后高考宽、找工作卷、房价回落。

## 文风

以 `docs/tianjin_style.md` 为准，年代这一层另有几条：

- **不写年份数字**。正文里不出现「一九九八」「98 年」；年代只用 `decades` 的名字和「八十年代末」「千禧年头上」这种说法。`year` / `born` / `until` 只给引擎。
- **敏感的十年不写**。没有哪件大事落在那十年，正文里也不提。考大学、分配、等分房写在 1963 年，就是为了让它们是「生之前的规矩」，不用去写那十年。以后要补，最多一笔带过，不展开，不评价。
- 不点品牌、真人、政策文件名，只用通称（停薪留职、保障房、售楼处、中介、扫码、拆迁办）。
- 大事写成楼里、街上看得见的变化（厂门口贴了名单、鏊子边上贴了张收钱的码），不写口号，不评价，不煽情。天津只做底色。
- 大事正文两个人看同一段，不写「你家」「你爸妈」；`hits.text` 才写「你」。
- 字数（按码点，标点也算）：`title` ≤ 7，`text` ≤ 45，`hits.text` ≤ 30，`cohort.note` ≤ 30，`decade.name` ≤ 6。build-content 查。

```bash
npm test                          # 内容校验（年代那一段的格式、单位、标记归属、纯新闻）+ 全部服务端测试

                                  # story.test 五个年代都抽（只在某个年代才有的事也要出得来）
node tools/eras.mjs               # 五个年代 × 12 种活法 × 16 条人生，过到 76 岁，打印下面那张表（4 核两分半到四分多钟）
node tools/eras.mjs --check       # 另加断言：c92 三十岁以前和 paths.mjs 逐条一致；别的年代至少有一条路和 c92 差 15 个点
node tools/eras.mjs --lives 40 --json out.json   # 人生多一点；JSON 里有每个年代 × 每种活法 × 每道关的计数
node tools/paths.mjs              # 只看 c92（默认年代）
```

`tools/eras.mjs` 用的就是 `tools/paths.mjs` 的机器人（`WAYS`、`live`、`climb`），种子也一样（第 i 条人生用 i × 7919），所以同一条人生在五个年代里只差出生年代。
它用子进程并行（`--jobs`，默认 CPU 个数）。`--check` 不过时退出码是 1。

改了 `eras.yaml` 以后至少看三样：c92 的 `--check` 还过；你想拉开的那条线在表上真拉开了；没想动的线没跟着动。

## 客户端显示了什么

客户端代码在 `client/scripts/ui/era.gd`（纯函数，单测 `client/tests/unit_era.gd`）。服务器发的字段都是可选的，老服务器不发，界面照老样子。

- **投胎页**：出生证上头写这一世两个人的出生年代（`life.cohort.name` 一行，`note` 小字一行）。
- **年代卡**：新的一天来的 `kind: "era"` 日志攒着，等关口揭晓、收工小结、长大和章首的墨卡都揭开了再弹；一张最多三件，点一下关，多了下一张。`hits` 只给本人看。不在河畔里时一行字带过。长卷纸边上一排「年代 · 标题」。
- **HUD**：日历牌的色条写「立春 · 九十年代」，青年往后写「青年 · 九十年代」，放不下就收一收。长大的过场卡小字也用年代名。
- **街景 look**：`world.era.look`（没有就看 `life.era.look`）代替人生阶段，选街景、远景（`world_view.set_look` → `scene_art`、`street_life`）和声景（`soundscape`）。人物外观、纸的旧、音乐还跟着岁数。

服务器那头：`eraView(s, c)` 给 life view 带 `cohort: { id, name, note }` 和 `era: { decade, look }`，WORLD 也带 `era`。不发年份。

## 已知没做的

- `look` 只能从现有的五套阶段美术里挑，没有按年代画的街景、物件、人物衣着。
- 二〇年代往后（延迟退休、楼里空了、装电梯）是往后推的，越往后越虚；c02 的晚年整段都在这里头。
- 机器人没有进厂的活法，`unit` / `quota`、下岗的 `hits` 和工钱打折、「厂门口」这一路在模拟里看不到。
- 「改制」（`lv_reform`）没有挂下岗那几年的门槛：挂上会让 c92 少一个岔口（gating_draft.md 第 3.3 节），先不加。`lv_sea`、`m_layoff` 也照旧哪个年代都有。
- 没有按年代分的结局文字、长卷收尾，`street.yaml` 的街景文案也还是按人生阶段走。
- 大事对两个人一样；两个人出生年代不同（不同岁）不在这个设计里。
- `era.test` 钉的是 c92 每条线的数不挪；「c92 走出来的人生和不带年代时逐条一样」没有进 `npm test`（要过好几百条人生），靠 `tools/eras.mjs --check` 手动跑。
